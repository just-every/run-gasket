# Gasket acceptance record

This is the build plan for every named clause of [CONTRACT.md](CONTRACT.md), including the full US mobile CMMS target and reliability agents. Status meanings match the contract: `done` means the scoped behavior has implementation and existing public-door test evidence; `partial` identifies a working slice and a remaining gap; `missing` has no implemented flow for that promise. A proposed journey below is required acceptance evidence, not a claim that a test already exists.

The existing form, JSON, page and download journeys run in `tests/gasket/flows.mjs` against the emitted Worker and real local D1, with invented fixtures only in tests and fakes only at network/provider boundaries. Their stable GAS-01 through GAS-13 test identifiers are retained. `tests/runtime.mjs` covers HTTP-001; `tests/email-link.mjs` covers Base sign-in. Future journeys use the same public-door standard, real native app/device/gateway paths where specified and provider sandboxes or captured network edges. No fixture implementation establishes a live integration, physical count, safety determination or certification.

## Running the proof

Use the repository's pinned Node and pnpm toolchain. `pnpm run build` emits the Worker, `pnpm run test:flows` executes the thirteen maintenance flows and `pnpm run test:runtime` executes HTTP-001. The Verify workflow runs the complete required wall on push. Base `rer check --profile first-party` validates the target contract's clause definitions and canonical Status table; publication scanning runs on the exact committed tree before push.

GAS-09 is done: each finding can name the checklist step it answers, and submission needs a linked finding for every failed or needs-attention step. GAS-11 is done: the flows run on a local installation, export it with `rer export`, restore the archive into an empty installation with `rer import` and read every record, history and attachment digest back unchanged. No existing test is removed or weakened. New permanent tests should prove the user flows as their implementations land, combining related journeys where appropriate rather than pinning document text or duplicating a test per paragraph.

## Boundaries

Local tests do not establish provider receipt, hosted rollout, complete exports from real vendor accounts, iOS/Android release distribution, offline device recovery, live sensor quality or an owner's physical maintenance cycle. A launch acceptance must exercise a real US buyer's equipment cycle, reconcile actual assets and spare-parts counts, complete the named incumbent's reconciled migration and test the connected providers under the owner's agreements. Missing paths stay partial or missing until their complete public-door journeys pass; they never reduce the target contract.
